# 报告写法

`REPORT.md` 由脚本生成，事实部分（表格、截图索引、令牌）不要手改；你只负责两件事：

1. 替换 `<!-- INSIGHT:START -->` 到 `<!-- INSIGHT:END -->` 之间的内容；
2. 在各章节表格下面补一到两句「所以呢」的解释。

## 洞察区块的三段结构

```markdown
## 一句话判断

<30–60 字。这个页面是什么风格、动效主张是什么、最值得学的一点是什么。必须具体，例如「深色底 + 高频微动效的开发者工具站：靠 2800ms 的网格呼吸动画和 90ms 按钮反馈建立科技感，没有一处动效超过 400ms」。禁止「整体风格现代简洁」这类空话。>

## 风格与设计语言

- **色彩**：主色/强调色/中性阶，各自的用法比例与对比策略（例如「近黑 #0B0B12 打底，仅用一个紫蓝 #6D5EFC 做强调，正文与背景对比约 16:1」）。
- **排版**：字阶（最小的正文到最大的标题的倍数关系）、字重跨度、字距策略（大标题负字距、正文 normal）、行高与信息密度。
- **几何与质感**：圆角体系（是否统一）、阴影层级、描边、毛玻璃/混合模式、留白节奏（区块间距是否收敛到 8px 网格）。
- **版式骨架**：hero 结构、栅格列数、内容宽度、吸顶导航行为。

## 可借鉴点与风险

- 可以直接搬走的 2–3 个手法（写明触发条件与参数，例如「卡片 hover：translateY(-6px) + scale(1.015) + 阴影扩散，350ms cubic-bezier(.22,1,.36,1)，只改合成层属性，不会触发重排」）。
- 复刻时容易踩的坑（字体授权、WebGL 依赖、动效在低端机掉帧、缺少 reduced-motion 分支）。
- 本次抓取没覆盖到的部分（明确说「未捕获」，不要编）。
```

## 批注的写法

- 每个数字都能在 `recon.json` 里找到出处；写「约」可以，写「估计」不行。
- 讲动效必须带三要素：**触发 → 属性变化 → 时长/缓动**。
- 讲交互必须区分 CSS 状态与 JS 行为（数据里 `hoverDiff` vs `listeners` / `waapiCalls`）。
- 截图与论述要对应：提到首屏就给 `01-hero.png`，提到 hover 就给 `20-hover-0X.png`。

## 章节增补示例

在「动效清单」表格后加：

> 站点的动效预算很克制：除两个装饰性循环动画（2800ms 网格呼吸、5000ms 浮动）外，所有交互反馈都落在 120–350ms 区间，缓动统一使用 `cubic-bezier(.22,1,.36,1)`。这意味着复刻时不需要引入动画库，纯 CSS 即可还原。

在「交互取证」后加：

> 按钮 hover 只改变 `transform` 与 `box-shadow`，不改宽高与外边距——这是它点击时不抖动的原因；active 追加 `scale(.96)`，120ms 线性回弹。

在「音效」后加：

> 页面本身没有环境音；点击主按钮时通过 Web Audio 合成 880Hz 正弦波（约 180ms 指数衰减），属于「提示音」而非「氛围音」。复刻时用一条 200ms 的短音即可，不要做循环背景音。
